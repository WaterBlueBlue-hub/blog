# 面向对象编程（OOP）
## 静态（Static）
&emsp;&emsp;静态是编程语言中的一个关键字和内存管理机制，它表示某个属性或方法属于类本身，而不是属于类的某一个具体实例。  
&emsp;&emsp;静态的两个核心特征：  
&emsp;&emsp;不需要实例化即可调用：不需要使用 new 关键字创建对象，直接用（类名.方法名）就可以执行。  
&emsp;&emsp;全局共享同一块内存：如果在一个类中定义了一个静态变量，那么无论你 new 出多少个对象，它们访问和修改的都是内存中的同一个值。  
## 抽象 (Abstraction)
&emsp;&emsp;抽象是指提取事物的本质特征，而隐藏底层的、非本质的实现细节。  
### 抽象类
&emsp;&emsp;抽象类是一个不能直接实例化（不能 new）的基类。它将相关的通用代码和强制规范结合在一起，通常包含两部分：  
&emsp;&emsp;普通方法：已经写好具体逻辑的代码，供所有子类直接继承复用。  
&emsp;&emsp;抽象方法：只有方法签名而没有任何具体代码体的方法，强制要求所有继承它的子类必须提供具体实现。  
&emsp;&emsp;虚方法：已经提供了默认的逻辑实现，但明确允许子类根据需要去重写（覆盖）它。如果子类不重写，则直接沿用父类的默认逻辑。
## 接口（Interface）
&emsp;&emsp;接口是一种完全抽象的行为规范。它只规定了一个类必须能做什么，但完全不规定它具体怎么做。  
&emsp;&emsp;它具有以下核心特征：  
&emsp;&emsp;不能直接实例化：不能使用 new 创建接口的对象。  
&emsp;&emsp;只包含声明：传统意义上，接口中只包含方法签名和常量，不包含具体的代码逻辑和普通成员变量。  
&emsp;&emsp;支持多实现：这是它和抽象类最大的区别。一个类只能继承一个父类，但可以同时实现多个接口。  
## 注册表（Registry）
&emsp;&emsp;注册表是一种集中存储、管理和查找对象实例或服务的架构模式。它的核心是维护一个键值对映射，将特定的标识符与具体的对象实例绑定起来。  
&emsp;&emsp;它的主要作用是解耦：调用方不需要使用 new 关键字去显式创建具体的对象，也不需要写大量的 if-else 来判断该实例化哪个类。调用方只需向注册表传入标识符，即可获取对应的对象并执行操作。
## 快照 (Snapshot)
&emsp;&emsp;捕捉并保存对象在某一特定时刻的完整状态。在设计模式中，这被称为备忘录模式。
## 缓存 (Cache)
&emsp;&emsp;将极其耗时或消耗性能的计算结果临时存储在内存中。当系统再次请求相同数据时，直接返回存储的结果，而不是重新计算。
## 脏标记 (Dirty Flag)
&emsp;&emsp;一个简单的布尔变量，用于标记对象的基础数据是否发生了改变。它通常与缓存配合使用，用于决定缓存数据是否已经失效。
## 前端 (Frontend / 客户端)
&emsp;&emsp;核心职责：界面渲染、接收用户输入、处理即时交互反馈。  
&emsp;&emsp;关注点：用户体验（UX）、界面布局（UI）、设备适配（如手机与电脑屏幕兼容）、响应流畅度。  
&emsp;&emsp;常见技术栈：Web 端的 HTML/CSS/JavaScript (React, Vue)；移动端的 iOS/Android 原生开发。  
## 后端 (Backend / 服务端)
&emsp;&emsp;核心职责：核心业务逻辑执行、数据持久化存储、系统级安全防御。  
&emsp;&emsp;关注点：数据一致性、防黑客攻击、高并发处理（如何同时服务十万人）、数据库架构。  
&emsp;&emsp;常见技术栈：C# (.NET), Java (Spring), Python, Go 等后端编程语言，配合 MySQL, Redis 等数据库系统。
